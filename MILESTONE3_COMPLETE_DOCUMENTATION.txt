1. EXECUTIVE OVERVIEW & MILESTONE 3 ARCHITECTURE ROADMAP
================================================================================
Milestone 3 represents the core cognitive layer of the LaunchLens platform. 
While Milestone 1 established structured data intake (startup projects, TAM/SAM/SOM 
market sizing, public NSE stock quotes) and Milestone 2 introduced quantitative 
risk scoring, SWOT matrices, and feasibility models, Milestone 3 transforms static 
metrics into dynamic, data-grounded intelligence.

Milestone 3 consists of three interconnected, production-grade tasks:

- TASK 1 (AI Strategic Recommendations): A multi-provider AI engine that 
  analyzes startup intake parameters alongside sector market metrics to generate 
  4 structured strategic pillars with data grounding rationales.
  
- TASK 2 (Mitigation & Improvement Engine): A contextual problem-solving engine 
  that scans market vulnerabilities (SOM contraction, category leader monopolies, 
  runway constraints) and synthesizes 8-point tactical mitigation plans.

- TASK 3 (LangGraph Multi-Agent Agent Workflow): An 8-node cyclic state-machine 
  graph built with @langchain/langgraph that executes data analysis, risk detection, 
  strategic synthesis, automated quality auditing, and conditional routing.

All three modules integrate directly into the existing Express backend and React 19 
frontend architecture without disrupting Milestone 1 or Milestone 2 features.

2.1 Multi-Provider AI Fallback Pipeline
--------------------------------------------------------------------------------
To guarantee 100% platform availability regardless of external API outages or key 
configurations, Task 1 implements a 3-tier fallback hierarchy:

Tier 1: Google Gemini API (@google/genai SDK targeting gemini-3.6-flash)
Tier 2: OpenAI REST API (gpt-4o-mini endpoint)
Tier 3: Deterministic Project Rule Engine (Zero external network dependencies)

Resolution Sequence:
1. Incoming POST request received at /api/recommendations/generate.
2. Check process.env.GEMINI_API_KEY. If present, invoke callGeminiApi().
3. callGeminiApi() tests candidate models (gemini-3.6-flash, gemini-3.5-flash, 
   gemini-1.5-flash) across SDK and REST endpoints.
4. If Gemini fails or key is missing, check process.env.OPENAI_API_KEY. If present, 
   call OpenAI gpt-4o-mini endpoint.
5. If both fail or no keys are configured, invoke generateFallbackRecommendations() 
   to return deterministic rule-based recommendations.

2.2 Input Prompt Synthesis & Metric Binding
--------------------------------------------------------------------------------
To eliminate generic AI statements, the backend constructs an explicit data-bound 
prompt containing:
- Project Form: Name, Industry, Business Model, Target Market, Budget, Description
- Market Sizing: TAM (₹ Cr), SAM (₹ Cr), SOM (₹ Cr), SOM Growth Rate (%)
- Competitor Share: Top competitor name, market share %, revenue, growth rate %

Prompt Rule Enforcement:
- Models must respond strictly in raw JSON without markdown text wrappers.
- Exactly 4 objects must be returned in the array.
- Every object must include a "rationale" key explicitly connecting the 
  recommendation to the project's numeric inputs.

2.3 Backend Service Implementation (backend/src/services/aiService.js)
--------------------------------------------------------------------------------
The service exports:
- generateAiRecommendations(projectData): Core entry point handling provider 
  resolution, prompt construction, JSON parsing, schema validation, and fallbacks.
- generateFallbackRecommendations(projectData): Deterministic engine producing 
  4 metric-derived strategy cards when external AI APIs are disabled.
- validateAndNormalizeRecommendations(parsedData): Normalization helper enforcing 
  allowed enum values for priority (critical, high, moderate, low), impact, effort, 
  and category.

3. TASK 2: MITIGATION & IMPROVEMENT SUGGESTION ENGINE
================================================================================

3.1 Context Signal Analysis & Problem Identification
--------------------------------------------------------------------------------
Task 2 addresses project vulnerabilities identified during analysis. It scans 
project metrics for 4 primary risk signals:
1. SOM Growth Signal: Contracting SOM growth (< 0%) or accelerating competition.
2. Competitive Concentration Signal: Category leader holding > 20% market share.
3. Financial Runway Signal: Capital constraints relative to business model CAC.
4. Sector Regulatory / Technical Signal: High-compliance sectors (Fintech/Healthcare) 
   or technical architecture friction.

3.2 8-Point Structured Mitigation Output Schema
--------------------------------------------------------------------------------
Every generated mitigation record provides a complete 8-point schema:
1. riskProblem: Specific vulnerability statement
2. possibleCauses: Root-cause analysis derived from market trends
3. severity: high | medium | low
4. mitigationStrategy: Tactical defense / risk containment plan
5. improvementSuggestion: Actionable product or business model optimization
6. priority: critical | high | moderate | low
7. recommendedAction: Concrete 30-day execution milestone
8. expectedOutcome: Target quantitative expected outcome metric

3.3 Backend Service Implementation (backend/src/services/mitigationEngine.js)
--------------------------------------------------------------------------------
The service exports:
- generateMitigations(projectData): Main execution handler invoking Gemini/OpenAI 
  APIs or deterministic fallbacks.
- generateFallbackMitigations(projectData): Deterministic synthesis function 
  analyzing somGrowth, topCompetitor share, budget, and industry regulations.

4. TASK 3: LANGGRAPH MULTI-AGENT AGENT WORKFLOW ENGINE
================================================================================

4.1 Framework Architecture (@langchain/langgraph)
--------------------------------------------------------------------------------
Task 3 implements autonomous agent orchestration using LangGraph (@langchain/langgraph 
and @langchain/core). Instead of static linear chains, LangGraph structures execution 
as a cyclic StateGraph with explicit state definitions, node handlers, and dynamic 
conditional transition edges.

4.2 Centralized State Channel Definition
--------------------------------------------------------------------------------
The state graph maintains a unified execution state containing:
- projectData: Raw input payload ({ form, market, competitors })
- dataAnalysis: Derived market growth & competitive concentration signals
- riskIdentification: Identified risk problems and critical risk flags (hasCriticalRisks)
- strategicRecommendation: 4 strategy pillars
- mitigationAnalysis: 4 tactical mitigation plans
- improvementSuggestions: Product & operational optimizations
- validationReview: Quality audit score (0-100) and review notes
- refinement: Refined rationale cards and action items
- finalDossier: Assembled executive report
- executionGraph: Array of execution step trace objects with node entry timestamps

4.3 Detailed 8-Node State Machine Breakdown
--------------------------------------------------------------------------------
1. dataAnalysis: Analyzes TAM/SAM/SOM growth rates and competitor share distribution.
2. riskIdentification: Scans for severe market vulnerabilities and sets hasCriticalRisks.
3. strategicRecommendation: Synthesizes strategic positioning pillars.
4. mitigationAnalysis: Formulates risk containment and defense strategies.
5. improvementSuggestions: Generates product & operational improvements.
6. validationReview: Evaluates complete dossier quality score (0-100) based on grounding.
7. refinement: Node triggered conditionally if qualityScore < 70 to enhance content.
8. finalSynthesis: Compiles complete strategic dossier and compiles step execution log.

4.4 Dynamic Conditional Edge Routing Mechanics
--------------------------------------------------------------------------------
The workflow incorporates two dynamic conditional edge functions:

Function 1: routeAfterRisk(state)
- If state.riskIdentification.hasCriticalRisks === true:
  Routes directly from riskIdentification -> mitigationAnalysis to prioritize 
  immediate risk containment before strategy synthesis.
- Else: Routes sequentially to strategicRecommendation.

Function 2: routeAfterValidation(state)
- If state.validationReview.qualityScore < 70:
  Routes from validationReview -> refinement node to enrich rationale statements.
- Else: Routes directly to finalSynthesis.

4.5 Backend REST API Contract (POST /api/workflow/run)
--------------------------------------------------------------------------------
Endpoint: backend/src/routes/workflow.js -> POST /api/workflow/run
Executes compiled StateGraph and returns:
{
  "success": true,
  "dossier": {
    "projectName": "TechQuest",
    "qualityScore": 88,
    "strategicPillars": [ ... ],
    "mitigationPlans": [ ... ],
    "executiveSummary": "..."
  },

  "executionGraph": [
    { "step": 1, "node": "dataAnalysis", "status": "COMPLETED", "timestamp": "2026-08-21T20:20:00.000Z" },
    { "step": 2, "node": "riskIdentification", "status": "COMPLETED", "timestamp": "2026-08-21T20:20:01.000Z" },
    ...
  ]
}

5. INTER-MILESTONE DATA FLOW & STATE SYNTHESIS (M1 -> M2 -> M3)
================================================================================
Data flows seamlessly through the application architecture without duplication:

1. INTAKE (ProjectInput.jsx): User submits form parameters.
   - POST /api/projects -> Stored in PostgreSQL projects table.
   - GET /api/market-data -> Fetches TAM/SAM/SOM metrics from database.
   - GET /api/competitors -> Fetches competitor shares + live NSE stock quotes.

2. REACT CONTEXT (ProjectContext.jsx): Stores single unified state.
   - State object: { form, market, competitors }

3. MILESTONE 2 COMPUTATIONS:
   - riskEngine.js computes 5 risk category meters on RiskAssessment.jsx.
   - feasibilityEngine.js computes 4 feasibility scores on FeasibilityAnalysis.jsx.

4. MILESTONE 3 AI & AGENT EXECUTION:
   - Recommendations.jsx calls POST /api/recommendations/generate (Task 1).
   - RiskAssessment.jsx calls POST /api/mitigations/generate (Task 2).
   - Recommendations.jsx calls POST /api/workflow/run (Task 3).

6. SECURITY POSTURE, SECRETS ISOLATION & ERROR RESILIENCE
================================================================================
- API Key Protection: GEMINI_API_KEY and OPENAI_API_KEY reside exclusively in 
  backend/.env and are NEVER exposed in frontend bundles or Vite client JS.
- Input Validation: Express routes validate request body structures and return 
  clean HTTP 400 responses on invalid payloads.
- Response Sanitization: Internal stack traces are logged on the server while 
  returning sanitized, safe JSON error objects to the client.
- Offline Fallback: If external AI services fail or keys are absent, deterministic 
  rule engines handle recommendations and mitigations cleanly with zero downtime.
